## The Opportunity: AI-Assisted Data Engineering On-Call

When production data pipelines fail, on-call data engineers typically repeat a manual sequence:
1. Navigate to the Airflow web server and search through thousands of lines of task instance logs.
2. Locate the failed step and extract the underlying BigQuery `job_id` or SQL exception.
3. Open Google Cloud Console, query `INFORMATION_SCHEMA.JOBS_BY_PROJECT`, and inspect slot contention, bytes billed, or schema mismatch.

By implementing an open-source **Model Context Protocol (MCP)** server, any MCP-compliant AI assistant (like Claude Desktop, Antigravity, or Cursor) can be granted safe, read-only analytical tools to triage and diagnose pipeline alerts automatically.

## Exposing FastMCP Tools for BigQuery Inspection

Using the Python `fastmcp` SDK, tools are defined with strict Pydantic docstrings so language models understand exactly when and how to invoke them:

```python
from mcp.server.fastmcp import FastMCP
from google.cloud import bigquery
from pydantic import BaseModel, Field

mcp = FastMCP("Data Pipeline Triage Server")
client = bigquery.Client()

@mcp.tool()
def analyze_bigquery_job(job_id: str) -> dict:
    """
    Inspects a completed or failed BigQuery job by ID.
    Returns slot utilization, total bytes processed, and execution stage bottlenecks.
    """
    job = client.get_job(job_id)
    
    stages_summary = []
    if hasattr(job, 'query_plan'):
      for stage in job.query_plan:
        stages_summary.append({
          "name": stage.name,
          "records_read": stage.records_read,
          "slot_ms": stage.slot_ms,
          "status": stage.status
        })

    return {
      "job_id": job.job_id,
      "state": job.state,
      "error_result": job.error_result,
      "total_bytes_billed_gb": (job.total_bytes_billed or 0) / (1024 ** 3),
      "total_slot_ms": job.total_slot_ms,
      "query_stages": stages_summary
    }
```

## Sample Agent Interaction: Automated Diagnostic

When an on-call engineer prompts:  
> *"Why did the transaction aggregation DAG fail at 03:00 UTC?"*

The agent:
1. Calls `get_dag_task_logs(dag_id="commercial_settlement_v2", execution_date="2025-01-14T03:00:00Z")`.
2. Identifies error: `Error during query execution: Resources exceeded during query execution: Your query exceeded the maximum slot limit.`
3. Calls `analyze_bigquery_job(job_id="bquxjob_7c8d9e")`.
4. Discovers a missing `PARTITION BY` filter causing an unintentional scan of 14 TB instead of the expected 12 GB daily partition.
5. Emits the exact 1-line SQL fix with line number references.
